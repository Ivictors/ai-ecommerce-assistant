# High-Level Technical Design — Backend Login and JWT Issuance

## Architecture

```text
Angular
  |
  v
AuthenticationResource
  |
  v
AuthenticationService
  |------------------> UserRepository
  |------------------> PasswordHasher (application port)
  |------------------> TokenIssuer (application port)
  |
  v
LoginResponse

Runtime RSA private key -> TokenIssuer signs JWT
Runtime RSA public key  -> Quarkus verifies JWT on protected endpoints
```

## Components

- `AuthenticationResource`: HTTP DTO validation and status mapping.
- `AuthenticationService`: credential lookup, hash verification, and token
  issuance orchestration.
- `PasswordHasher`: application port for Argon2id verification.
- `TokenIssuer`: application port for signed access-token creation.
- `UserRepository`: infrastructure persistence lookup by email.
- `User`: persisted role and password-hash state.

## API Contract

`POST /api/auth/login`

Request:

```json
{
  "email": "customer@example.com",
  "password": "secret"
}
```

Success `200 OK`:

```json
{
  "accessToken": "eyJ...",
  "tokenType": "Bearer",
  "expiresIn": 3600
}
```

Invalid credentials: `401 UNAUTHENTICATED` with a uniform safe message.
Malformed input: `400 INVALID_REQUEST`.

## JWT Claims

- `iss=ecommerce`;
- `sub=<numeric user id>`;
- `role=<persisted user role>`;
- `iat` and `exp` generated by the issuer.

Quarkus SmallRye JWT maps the `role` claim to the caller's security groups via
`smallrye.jwt.path.groups=role`. This mapping is required for `@RolesAllowed`
to enforce the persisted `USER`/`ADMIN` role on protected resources. Keep this
setting aligned between runtime configuration, the example configuration,
and integration-test configuration.

The exact lifetime must be runtime-configured and documented in the low-level
design; it must not be hardcoded into a controller.

## Persistence

Add a Flyway migration for:

- `users.password_hash`;
- `users.role`;
- constraints/defaults required for existing seeded users.

Existing users receive `USER` as the database default role. Their
`password_hash` remains null until the secure provisioning workflow tracked by
issue #44 is implemented. Authentication rejects users with a null hash.

Argon2id parameters are runtime-configurable. The approved initial defaults
are 64 MiB memory, 3 iterations, parallelism 1, and a 32-byte hash output.
The access-token lifetime is runtime-configurable with an approved initial
default of 15 minutes (`PT15M`). The RSA private-key and public-key locations
are runtime-configurable and default to local `privateKey.pem` and
`publicKey.pem` paths respectively; the JWT issuer is configurable and
defaults to `ecommerce`.

Existing migrations must not be modified.

## Security

- Credentials are accepted only over the login request boundary and never
  returned.
- Invalid email and invalid password use the same failure response.
- RSA private key is runtime-only and ignored by Git.
- Role is loaded from persistence, not request input.
- JWT verification remains server-side and independent of Angular guards.

## Test Map

- Authentication service valid/invalid credentials.
- Argon2id hash and mismatch behavior.
- JWT claims and expiration.
- REST login status and safe error payload.
- Issued token accepted by a protected endpoint.
- USER versus ADMIN authorization using issued tokens.
- Role claim is mapped to Quarkus security roles and enforced by a protected
  admin-only endpoint.
- No secret/password/token logging.
